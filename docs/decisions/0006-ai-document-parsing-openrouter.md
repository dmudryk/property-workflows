## Контекст

Зріз 4 додає AI-розбір документа в запуску: менеджер запуску вставляє лист орендаря, розшифровку дзвінка чи кошторис
вендора, AI пропонує значення (телефон, опис, категорію, терміновість або позиції кошторису й total), а людина
перевіряє, виправляє й лише тоді зберігає їх (`openspec/specs/document-parsing/spec.md`, тимчасові AC розробника).
Обмеження:

- Next.js 16.4 на Vercel Hobby: функція працює до 300 с; Server Action приймає тіло до 1 МБ за замовчуванням.
- Модель — безкоштовна через OpenRouter, ключ — власний у розробника. Ліміт безкоштовних моделей — 20 запитів/хв і
  50/день на акаунт; додаткові ключі ліміту не збільшують. Безкоштовні моделі з'являються й зникають.
- Безкоштовні ендпоінти можуть зберігати й використовувати запити для навчання → лише синтетичні дані.
- Відповідь моделі недетермінована, а CI має бути без мережі й без секретів.
- Документ — недовірений текст із ін'єкціями («Ignore all previous instructions…», кейс PM GC-10).

## Рішення

- Нові залежності (точні версії): `ai@7.0.162`, `@openrouter/ai-sdk-provider@3.1.0`, `zod@4.6.7`, `server-only@0.0.1`.
- Виклик — `generateText` + `Output.object({ schema })` (AI SDK 7). Схема zod (`src/lib/ai/schema.ts`):
  `status: ok | refused`, тип документа, поля заявки (переліки PM), позиції кошторису й total, нотатки, прапорець
  `injectionIgnored`; «невідоме» = `null`. Відповідь не за схемою — помилка, а не чернетка.
- Чиста функція `proposeDocument(input, model)` (`src/lib/ai/draft.ts`) отримує модель параметром; ключ читає лише
  `src/lib/ai/openrouter.ts` з `import "server-only"`. Змінна — `OPENROUTER_API_KEY`, без `NEXT_PUBLIC_`.
- Правила, які можна перевірити кодом, — у коді після моделі (`src/lib/ai/document-rules.ts`): одна форма телефону й
  відкидання телефону, якого немає в документі; сума кошторису й текст попередження; нотатка ін'єкції; відмова без
  значень. Ті самі правила й повторна валідація zod — перед записом.
- Ланцюжок моделей (лише `:free`): `nvidia/nemotron-3.5-super-vl:free` (строга схема) →
  `google/gemma-4-31b-it:free` → `google/gemma-4-26b-a4b-it:free`; суддя живого eval — теж ланцюжок моделей інших
  родин зі строгою схемою: `inclusionai/ling-3.2-flash:free` → `baidu/ernie-5.5-flash-preview:free` →
  `particle-ai/particle-1:free` (перший прогін 16.11 з одним суддею Gemma обірвав 429 постачальника, хоча денний ліміт
  був 0 із 50). `maxRetries` 1 у застосунку, 0 у живому eval.
- Людина в контурі: Server Action пропозиції нічого не пише; запис — окрема дія «Save values» через функцію бази
  `save_run_document` (ADR 0001) під сесією користувача. Обидві дії спершу перевіряють `getClaims()` і роль.
- Перевірка якості: 10 golden cases PM (solomchaak/property-workflows-spec#40). Офлайн-реплей записаних відповідей
  (`MockLanguageModelV4`) — у `npm test` (CI); живий прогін — `npm run eval` вручну, зі звітом частки успіху за моделлю в
  `evals/reports/`.

## Розглянуті варіанти

- Claude Agent SDK у функції Vercel — ні: SDK запускає підпроцес Claude Code (~320–342 МБ), а пакет функції
  Vercel — до 250 МБ; до того ж тут потрібен один виклик моделі, а не агентний цикл.
- Пакет `openai` з `baseURL` OpenRouter або `@openrouter/sdk` — ні: немає валідації схемою з типізованими
  помилками й тестових моделей (`MockLanguageModelV4`) в одному API.
- `openrouter/free` (випадкова безкоштовна модель) — ні: результат golden cases не відтворюється.
- Gemma першою (як у заготовці) — ні: без `structured_outputs` схема може бути проігнорована; Super VL її тримає.
- Файли (PDF, зображення) — не в цьому зрізі: лише вставлений текст, тож плагін `file-parser` не потрібен.

## Наслідки

- Простіше: провайдера й модель міняємо в одному файлі; CI не залежить від мережі та ліміту.
- Складніше: безкоштовна модель може зникнути або впертися в ліміт — інтерфейс показує «The assistant is not
  available right now. Enter the values yourself.», а людина заповнює форму вручну. Ланцюжок перевіряємо
  `npm run ai:models` перед роботою.
- Записи `tests/fixtures/golden/recorded.json` треба оновлювати (`RECORD=1 npm run eval`), коли змінюється промпт
  (`DRAFT_PROMPT_VERSION`) або схема.
- Коли PM опублікує вимогу з AC, тимчасові AC зміняться, а з ними — переліки схеми й тексти повідомлень.
